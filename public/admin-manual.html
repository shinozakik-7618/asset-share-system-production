🌐 1. システム概要

📋 システムの目的

拠点資産シェアシステムは、複数の拠点間で資産を共有・譲渡するための管理システムです。
各拠点の資産を一元管理し、効率的な資産活用を実現します。

🔑 主な機能

機能 説明
資産登録・管理 資産の登録、編集、削除、公開/非公開の管理
譲渡申請 他拠点への資産譲渡申請と承認フロー
経費振替 資産譲渡に伴う経費の振替処理
通知機能 申請・承認・却下の通知
統計ダッシュボード 資産数、カテゴリ、拠点別の統計表示
履歴管理 資産の登録・編集・ステータス変更履歴

🏗️ システム構成

【技術スタック】 ・フロントエンド: HTML, CSS, JavaScript ・バックエンド: Firebase (Authentication, Firestore, Storage, Hosting) ・認証方式: Googleアカウント認証、メール/パスワード認証 ・データベース: Cloud Firestore (NoSQL) ・ファイルストレージ: Firebase Storage ・ホスティング: Firebase Hosting

⚙️ 2. 初期設定

🔐 Firebaseプロジェクトの設定

1
Firebase Consoleにアクセス
https://console.firebase.google.com/ にアクセスします
2
プロジェクトを選択
プロジェクト名：base-asset-sharing-system
3
認証設定を確認
左メニューの「Authentication」→「Sign-in method」で以下を確認：
✅ Google（有効）
✅ メール/パスワード（有効）

📊 Firestoreインデックスの確認

1
Firestoreダッシュボードを開く
左メニューの「Firestore Database」をクリック
2
インデックスタブを確認
以下のインデックスが作成されていることを確認：
• assetHistory: assetId (昇順), timestamp (降順)
• notifications: userId (昇順), read (昇順)
• notifications: userId (昇順), timestamp (降順)
重要： インデックスが作成されていない場合、履歴や通知が正しく表示されません。
エラーメッセージのURLから自動的にインデックスを作成できます。

🗂️ Firestoreコレクション構造

【主要コレクション】 📁 users - ユーザー情報 └─ {userId} ├─ displayName: string ├─ email: string ├─ baseId: string ├─ baseName: string ├─ region: string ├─ block: string └─ createdAt: timestamp 📁 assets - 資産情報 └─ {assetId} ├─ assetName: string ├─ quantity: number ├─ amount: number (税抜金額) ├─ largeCategory: string ├─ mediumCategory: string ├─ userId: string ├─ baseId: string ├─ status: string (available/unavailable) ├─ forTransfer: boolean ├─ qrCodeText: string └─ createdAt: timestamp 📁 baseMaster - 拠点マスタ └─ {baseId} ├─ baseName: string ├─ region: string └─ block: string 📁 transferRequests - 譲渡申請 └─ {requestId} ├─ assetId: string ├─ fromUserId: string ├─ toBaseId: string ├─ status: string (pending/approved/rejected) └─ createdAt: timestamp 📁 expenseTransfers - 経費振替 └─ {expenseId} ├─ assetId: string ├─ amount: number ├─ fromBaseId: string ├─ toBaseId: string └─ createdAt: timestamp 📁 assetHistory - 資産履歴 └─ {historyId} ├─ assetId: string ├─ action: string (created/edited/status_changed) ├─ details: object └─ timestamp: timestamp 📁 notifications - 通知 └─ {notificationId} ├─ userId: string ├─ type: string ├─ message: string ├─ read: boolean └─ timestamp: timestamp

👥 3. ユーザー管理

➕ 新規ユーザーの追加

1
Firebase Consoleで認証設定
「Authentication」→「Users」→「Add user」
2
メールアドレスとパスワードを設定
• メールアドレス：ユーザーのメールアドレス
• パスワード：初期パスワード（8文字以上）
3
ユーザーに初回ログイン情報を通知
メールアドレスとパスワードを安全な方法で伝えます
4
ユーザーに初回設定を依頼
初回ログイン時に、ユーザー登録画面で名前と拠点を設定してもらいます
ヒント： ユーザーは「⚙️ 設定」画面から、いつでも名前や拠点を変更できます

🔍 ユーザー情報の確認

1
Firestoreダッシュボードを開く
「Firestore Database」→「データ」タブ
2
usersコレクションを確認
各ユーザーのdocumentで以下を確認できます：
• 名前（displayName）
• メールアドレス（email）
• 所属拠点（baseName, region, block）
• 登録日時（createdAt）

❌ ユーザーの削除

注意： ユーザーを削除すると、そのユーザーが登録した資産も影響を受ける可能性があります。
削除前に必ず確認してください。
1
Firebase Authenticationで削除
「Authentication」→「Users」→ 削除したいユーザーの「...」→「Delete account」
2
Firestoreのユーザーデータを削除
「Firestore Database」→「users」コレクション → 該当documentを削除

🏢 4. 拠点マスタ管理

➕ 新しい拠点の追加

1
Firestoreダッシュボードを開く
「Firestore Database」→「データ」タブ
2
baseMasterコレクションを開く
コレクション一覧から「baseMaster」を選択
3
「ドキュメントを追加」をクリック
以下のフィールドを入力：
【入力例】 ドキュメントID: （自動ID） フィールド: baseName (string): "東京本社" region (string): "関東" block (string): "東日本"
ヒント： 拠点の階層は「ブロック > 地域 > 拠点」の3段階です

✏️ 拠点情報の編集

1
baseMasterコレクションで対象拠点を選択
編集したい拠点のdocumentをクリック
2
フィールドの値を編集
鉛筆アイコンをクリックして値を変更し、保存します
注意： 拠点名を変更すると、既存の資産データには反映されません。
拠点名変更時は、関連する資産のbaseNameも更新する必要があります。

📊 拠点データのエクスポート

1
Firestore Consoleで拠点一覧を表示
baseMasterコレクションを開きます
2
データをコピー
必要に応じて、スクリーンショットやCSVエクスポートツールを使用します

✅ 5. 譲渡申請の承認・却下

📋 譲渡申請の確認方法

1
譲渡承認画面にアクセス
ホーム画面の左メニューから「譲渡承認」をクリック
2
タブで申請状態を確認
• 承認待ち：未処理の申請
• 承認済み：承認された申請
• 却下済み：却下された申請
3
申請内容を確認
• 資産名
• 申請者
• 譲渡元拠点
• 譲渡先拠点
• 申請理由
• 配送方法

✅ 譲渡申請の承認

1
「承認する」ボタンをクリック
承認待ちの申請カードの緑色のボタンをクリックします
2
確認ダイアログでOKをクリック
「この譲渡申請を承認しますか？」→「OK」
3
自動処理の確認
承認すると、以下が自動的に実行されます：
✅ 申請ステータスが「承認済み」に変更
✅ 資産の所属拠点が譲渡先に変更
✅ 経費振替データが自動作成
✅ 申請者に通知が送信
✅ メール通知が送信
承認完了！ 申請者には自動的に通知が届きます

❌ 譲渡申請の却下

1
「却下する」ボタンをクリック
承認待ちの申請カードの赤色のボタンをクリックします
2
却下理由を入力
ダイアログで却下理由を入力します（必須）
例：「在庫不足のため」「別の拠点に譲渡済み」
3
OKをクリック
却下理由と共に申請が却下されます
4
自動処理の確認
却下すると、以下が自動的に実行されます：
✅ 申請ステータスが「却下済み」に変更
✅ 却下理由が記録される
✅ 申請者に却下通知が送信
✅ 資産の状態は変更されない
ヒント： 却下理由は申請者に表示されるため、具体的で分かりやすい理由を記入してください

💰 6. 経費振替の管理

📊 経費振替の確認

1
経費振替画面にアクセス
ホーム画面の左メニューから「経費振替」をクリック
2
振替一覧を確認
以下の情報が表示されます：
• 資産名
• 振替元拠点
• 振替先拠点
• 金額（税抜）
• 振替日
• 理由
ヒント： 経費振替データは、譲渡申請が承認されると自動的に作成されます

➕ 手動での経費振替登録

1
「➕ 経費振替を登録」ボタンをクリック
画面上部のボタンをクリックします
2
必要な情報を入力
• 資産名
• 振替元拠点
• 振替先拠点
• 金額（税抜）
• 振替日
• 理由
3
「登録する」ボタンをクリック
入力内容を確認して登録します

🗑️ 経費振替の削除

1
削除したい振替の「削除」ボタンをクリック
振替カードの赤色の削除ボタンをクリックします
2
確認ダイアログでOKをクリック
削除を確認して実行します
注意： 削除した経費振替データは復元できません

📤 経費振替データのエクスポート

1
Firestoreダッシュボードを開く
「Firestore Database」→「expenseTransfers」コレクション
2
データをエクスポート
必要に応じて、サードパーティツールを使用してCSV形式でエクスポートできます

📊 7. 統計データの確認

📈 統計ダッシュボードの見方

1
統計画面にアクセス
ホーム画面のヘッダーにある「📊 統計」ボタンをクリック
2
4つの統計カードを確認
• 📦 総資産数：システム全体の資産数
• 📝 登録資産数：自分が登録した資産数
• ⏳ 承認待ち：処理待ちの譲渡申請数
• 📂 カテゴリ数：資産のカテゴリ種類数
3
グラフで視覚的に分析
• カテゴリ別資産数（円グラフ）
• 月別登録数（棒グラフ）
• 拠点別資産数（棒グラフ）
活用方法：
• カテゴリ別グラフで資産の偏りを確認
• 月別グラフで登録の推移を分析
• 拠点別グラフで各拠点の資産保有状況を把握

🔍 詳細データの確認

1
Firestoreで直接確認
より詳細なデータが必要な場合は、Firestore Consoleで直接確認できます
2
クエリを実行
特定の条件でデータを抽出する場合は、Firestoreのクエリ機能を使用します

🔧 8. トラブルシューティング

❌ よくあるエラーと対処法

エラー：「The query requires an index」
原因： Firestoreのインデックスが作成されていない
対処法：
1. エラーメッセージ内のURLをクリック
2. 「インデックスを作成」ボタンをクリック
3. 2〜5分待つ
4. ステータスが「有効」になったら完了
エラー：「firebase.storage is not a function」
原因： Firebase Storage SDKが読み込まれていない
対処法：
HTMLファイルに以下のスクリプトタグを追加：
<script src="https://www.gstatic.com/firebasejs/9.22.0/firebase-storage-compat.js"></script>
問題：履歴が表示されない
原因： assetHistoryコレクションのインデックスが未作成
対処法：
1. 履歴画面を開いてエラーを確認
2. ブラウザのコンソール（F12）でエラーURLを確認
3. URLをクリックしてインデックスを作成
問題：通知が届かない
原因： notifications.jsが読み込まれていない、またはインデックスが未作成
対処法：
1. HTMLファイルに<script src="/js/notifications.js"></script>が含まれているか確認
2. notificationsコレクションのインデックスを確認
3. ブラウザのコンソールでエラーを確認

🔍 デバッグ方法

1
ブラウザの開発者ツールを開く
Chrome: Command + Option + J (Mac) / F12 (Windows)
Safari: Command + Option + C (Mac)
2
Consoleタブでエラーを確認
赤色のエラーメッセージを確認します
3
Networkタブで通信を確認
API呼び出しが正常に行われているか確認します
ヒント： エラーメッセージをコピーしてGoogle検索すると、解決策が見つかることが多いです

📤 データのエクスポート

1
Firebase Consoleを開く
https://console.firebase.google.com/
2
Firestoreダッシュボードを開く
左メニューの「Firestore Database」をクリック
3
エクスポート機能を使用

【Firebase CLIでのエクスポート例】 firebase firestore:export gs://[BUCKET_NAME]/[EXPORT_PREFIX] 例： firebase firestore:export gs://base-asset-sharing-system.appspot.com/backups/2024-01-02
